We believe the best tools are open.

Luna is an open-source project aimed as a scaffold agent platform — to allow anyone to build reliable, relatable, self-reflective, self-improving agents.

Everything that makes Luna an agent is open.

The hosted service adds convenience — signup, billing, provisioning. The agent itself is fully open.

Open — MIT licensed

  • ✓ Agent core (~4,600 LOC)
  • ✓ Memory system (MemoryProvider + plugin-memory)
  • ✓ Encrypted vault (VaultProvider + plugin-vault)
  • ✓ Approval gates & interrupt engine
  • ✓ Plugin system & SDK
  • ✓ All 20+ platform plugins
  • ✓ All channel adapters (Slack, WhatsApp, Telegram, email)
  • ✓ Code execution engine
  • ✓ Self-improvement system
  • ✓ Web UI
  • ✓ All documentation (CC BY 4.0)

Proprietary — the service layer

  • Control plane (signup, billing, provisioning)
  • Fleet management dashboard
  • Vertical knowhow packs (e.g. marketing)
  • Operational monitoring

None of this is needed to run Luna. It's the service we sell so we can keep building the open platform.

A scaffold you can build on.

Small core, plugin-everything architecture. Every component is swappable, every decision is auditable.

🧠

pydantic-ai agent engine

Structured, type-safe execution. pydantic-ai owns the LLM loop and tool dispatch. Approval gates are hard interrupts in the execution flow, and all state is persisted to Postgres.

🗄️

Postgres is the brain

Messages, actions, costs, approvals, memory, identity, plugins, versions, workflow checkpoints — all in Postgres with pgvector for semantic search. Everything queryable. Everything exportable.

🔌

Plugin-everything

Core is ~4,600 lines. Everything else is a plugin: memory, vault, cost tracking, channels, code execution, learning, scheduling, cloning. System apps define interfaces (MemoryProvider, VaultProvider) — swap implementations without changing core.

🚦

Hard approval gates

Not prompt instructions. The execution engine hits a hard gate and literally pauses. The LLM cannot continue until the user clicks. Scoped decisions (once / today / forever) stored in DB, visible in UI, revocable.

🔐

Per-tenant isolation

Each agent gets its own database schema, encryption key, and filesystem. In the hosted service, each agent is a separate Fly Machine (microVM). The vault derives per-tenant keys — we can't decrypt your credentials.

📡

Event bus, not imports

Plugins communicate via an internal event bus — they never import each other. Crash-isolated (one bad plugin can't kill the agent). Each plugin gets its own DB namespace, network egress allowlist, and lifecycle hooks.

Standard tools. No surprises.

Python 3.12+ · pydantic-ai · FastAPI · PostgreSQL + pgvector · React + Vite · Docker

If you've built a Python web app, you already know this stack. No exotic dependencies, no proprietary runtimes, no vendor-specific SDKs. Clone it, read it, run it.

$ git clone https://github.com/huemorgan/luna
$ cd luna
$ docker compose up
# Luna is running at localhost:8000
