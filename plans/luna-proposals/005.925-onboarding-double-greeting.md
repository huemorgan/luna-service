# Proposal for Luna — Onboarding Double-Greeting Fix

> This is a PROPOSAL written in the luna-service repo. It is NOT a Luna
> plan yet. If accepted, it gets recreated inside the Luna project by
> whoever works there (suggested number: 005.925) and executed via
> Luna's own process. Nothing in `luna/` is touched from here.

## Bug (observed in hosted mode, 2026-06-10; core Luna behavior)

First-run flow:

1. UI calls `POST /api/onboarding/start`. A "Getting started"
   conversation is created and Luna speaks first via a **non-persisted**
   kickoff control message. Her greeting IS persisted:
   *"Hey there! I'm a brand-new agent… What should I call you?"*
2. The owner replies with something that isn't a name — e.g. "you here?".
3. Luna re-introduces herself almost verbatim and re-asks for a name.

Why: the onboarding addendum (`onboarding.frame` seed — "You're a
brand-new agent meeting your owner for the first time") is injected
identically on every turn until setup completes. Nothing tells the model
the greeting already happened, and the kickoff control message that
prompted it isn't in history.

This is the first interaction every new user has with the product.

## Suggested fix

Make the addendum state-aware:

1. Where the onboarding addendum is assembled (`plugin_api/app.py`),
   compute `already_greeted: bool` — true iff the conversation history
   contains at least one assistant message.
2. Pass it into the addendum renderers in `luna/onboarding/prompts.py`.
3. When `already_greeted`, swap the frame line for a continuation frame,
   seeded as a new editable prompt key `onboarding.frame_continue`:

   > "You are mid-setup with your owner — you have already introduced
   > yourself. Do NOT introduce yourself again or repeat your opening
   > question as a script. Respond to what the owner actually said, in
   > your own voice, then continue setup from the SETUP STATE block."

4. Seed migration + fallback in `luna/prompts/seeds.py`.

## Suggested tests

- Unit: addendum renders first-contact frame with empty history,
  continuation frame once an assistant message exists; new prompt key
  seeded.
- Dojo: fresh agent → greeting streams → send "you here?" → PASS iff no
  re-introduction, onboarding continues naturally. Second scenario:
  unrelated detour → answered briefly + steered back without re-intro.
