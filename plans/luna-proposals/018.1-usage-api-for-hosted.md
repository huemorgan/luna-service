# Proposal for Luna — Usage Summary API for Hosted Mode

> This is a PROPOSAL written in the luna-service repo. It is NOT a Luna
> plan yet. If accepted, it gets recreated inside the Luna project
> (suggested number: 018.1, as an addendum to Phase 018
> `cost-rate-limiter`) and executed via Luna's own process. Nothing in
> `luna/` is touched from here.

## Why luna-service needs this

The control plane needs to read each agent's LLM spend programmatically
for per-account rollups, spend alerts, and eventually billing (see
`plans/012-platform-hardening/PLAN.md` § 012.4). Luna Phase 018 already
plans per-call cost records (`plugin_cost_records`), cost tools, and a
Costs UI — but no machine-readable endpoint for the platform that hosts
her.

## What we're asking for

One read-only endpoint on `plugin-cost`'s API surface:

```
GET /api/p/plugin-cost/usage/summary?from=YYYY-MM-DD&to=YYYY-MM-DD
```

Response shape:

```json
{
  "from": "2026-06-01",
  "to": "2026-06-10",
  "total_usd": 4.31,
  "days": [
    {"date": "2026-06-01", "usd": 0.42,
     "input_tokens": 181000, "output_tokens": 24000,
     "by_model": {"anthropic:claude-sonnet-4": 0.42}}
  ]
}
```

- Aggregated from `plugin_cost_records` — no new tables.
- Auth: same as every API route (session normally, trusted-proxy headers
  in hosted mode). No special service token needed.
- Defaults: `to` = today, `from` = first of current month.
- Plugin disabled → route 404s like any disabled plugin's routes;
  callers treat that as "no data".

## Non-goals

- Push/webhook reporting (the platform polls).
- Budget enforcement (that's `plugin-rate-limiter`, 018 proper).
- Cross-agent aggregation (the platform does that).
